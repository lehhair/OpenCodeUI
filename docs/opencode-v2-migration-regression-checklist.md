# OpenCodeUI × OpenCode V2 —— 手工回归清单

> 面向**非专业用户**。每一步都写清「**点哪里 → 看到什么算通过 → 不通过时记录什么**」。
> 适用版本：本 UI **只支持 OpenCode v2**（开发与验证基线 `v2.0.19`）。
> 配套报告：`docs/opencode-v2-migration-phase4.md`

---

## 0. 开工前的三件事（很重要）

### 0.1 先确认你的 opencode 是 v2

在终端里执行：

```bash
opencode --version
```

- ✅ **通过**：输出类似 `opencode v2.0.19`（**以 `v2.` 开头**）。
- ❌ **不通过**：输出 `1.18.x` 之类。**不要继续** —— 本 UI 打不开 v1 后端。
  按下面第 0.2 条装 v2。
- 📝 **记录**：把这一行原文抄下来（版本号 + 后面的数字）。

### 0.2 如果还是 v1（或没装）

```bash
curl -fsSL https://opencode.ai/v2/install | bash
```

> ⚠️ **不要**用 `https://opencode.ai/install`。那个老脚本会从 GitHub 的「最新发布」下载，
> 而 GitHub 上的最新发布**是 v1**（`v1.18.33`）—— 装完还是连不上。
> 装完**再跑一次** `opencode --version` 确认是 `v2.`。

### 0.3 备份你的配置（可选但推荐）

```bash
cp ~/.config/opencode/opencode.jsonc ~/.config/opencode/opencode.jsonc.bak
```

> 本 UI 的「配置查看器」**只会写 `shell` 一个字段**（其它字段改不了）。
> 但先备份总是稳的。

## 1. Docker 形态

### 1.1 构建

在项目根目录执行：

```bash
docker compose -f docker-compose.yml -f docker-compose.build.yml build
```

- ✅ **通过**：最后出现 `naming to ...opencodeui-backend:local` 之类，**没有红字 `ERROR`**。
  构建日志里应能看到 `opencode v2.0.19` 这一行（这是构建时的版本自检）。
- ❌ **不通过**：
  - 出现 `sha256sum: WARNING: 1 computed checksum did NOT match` → **上游文件变了**，
    需要重算哈希（见 `docs/opencode-v2-migration-phase4.md` §1）。
  - 出现 `curl: (22) ... 404` → 版本号写错，检查 `OPENCODE_VERSION`。
- 📝 **记录**：完整报错段落（含它前面 20 行）+ `docker --version` 输出。

### 1.2 启动

```bash
docker compose -f docker-compose.yml -f docker-compose.build.yml up -d
```

### 1.3 🔴 先验版本（**这一步最容易漏，但最关键**）

```bash
docker compose exec backend opencode --version
```

- ✅ **通过**：输出 `opencode v2.0.19`（**以 `v2.` 开头**）。
- ❌ **不通过**：
  - 输出 `1.18.x` → **你用的是旧镜像**。执行 `docker compose -f docker-compose.yml -f docker-compose.build.yml build --no-cache backend` 重新构建；
    若用的是预构建镜像则先 `docker compose pull backend`。
  - 输出 `WARNING: opencode 版本不是 V2（...）` → 同上（这是启动脚本主动喊出来的版本守卫）。
- 📝 **记录**：`opencode --version` 原文 + `docker compose images backend` 输出的镜像 ID 与创建时间。

### 1.4 打开界面

浏览器访问 `http://localhost:6658`（默认网关端口）。

- ✅ **通过**：界面正常加载，没有一直转圈。
- ❌ **不通过**：白屏 / 一直转圈 / 右上角显示服务异常。
- 📝 **记录**：浏览器 F12 → Console 的红色报错；F12 → Network 里失败请求的 URL 与状态码。

### 1.5 发一条消息

在输入框打「你好」，回车。

- ✅ **通过**：消息立刻出现在列表里，随后**一个字一个字地流式**出现回复；回复结束后输入框恢复可用。
- ❌ **不通过**：消息发出后**永远没有回复**（这是 v1/v2 不匹配最典型的表现）。
- 📝 **记录**：卡住时的截图 + `docker compose logs backend --tail 100` 的输出。

### 1.5b 切换模型后发送（🔴 2026-09-30 修复点）

在输入框上方的**模型选择器**里换一个模型（比如从当前模型换成另一个），
然后发一条「只回复一个字：好」。

- ✅ **通过**：
  1. 回复**立刻出现**；
  2. 回复条目**底部（step 信息处）显示的模型名 = 你刚换的模型**；
  3. 若这是本会话里第一次真正换模型，消息流里会出现一条「**切换模型**」的记录
     （正常现象，与官方 TUI 一致；没换模型则不会出现）。
- ❌ **不通过**：回复底部的模型名仍是旧模型 / 默认模型（说明前端镜像还是旧的，需重新构建）。
- 📝 **记录**：截图（含模型选择器 + 回复底部的模型名）。

### 1.6 中断

再发一条「写一个 500 字的自我介绍」，等它开始输出后点**停止按钮**（发送按钮会变成停止）。

- ✅ **通过**：输出**立刻停住**，消息保留在列表里，界面不报错、不卡死。
- ❌ **不通过**：点了没反应；或弹出红色报错；或整个界面卡死。
- 📝 **记录**：点击前后的截图 + Console 报错。

### 1.7 回退（撤销上一轮）

鼠标移到**你的那条消息**上 → 点出现的「回退」按钮 → 确认。

- ✅ **通过**：那一轮之后的内容从列表里消失；界面提示可以「恢复」；点恢复能回来。
- ❌ **不通过**：点了没反应；或报错；或文件没回到旧内容。
- 📝 **记录**：操作步骤（点了几次、点了哪个按钮）+ 截图。

### 1.8 表单（AI 反问你）

发一条会触发提问的消息，例如：
「用 question 工具问我一个选择题：今天喝咖啡还是茶？」

- ✅ **通过**：界面**底部**弹出表单，能选项、能提交；提交后 AI 继续回答。
- ❌ **不通过**：底部不弹表单；或弹了但提交无反应。
- 📝 **记录**：截图 + Console 报错 + `docker compose logs backend --tail 50`。

### 1.9 配置查看器

左下角设置 → 「配置」标签 → 「打开配置查看器」。

- ✅ **通过**：
  1. 弹窗打开，能看到「当前生效配置」的字段列表；
  2. 顶部有说明「为什么其它字段改不了」；
  3. **`shell` 那一段**有下拉框和「保存 shell」按钮；
  4. 点某字段的「复制 JSON」，剪贴板里能粘出内容。
- ❌ **不通过**：弹窗打不开；或出现「保存全部」这类按钮（那是旧版本）。
- 📝 **记录**：截图 + Console 报错。

### 1.10 配置写入（唯一可写项）

在 1.9 的弹窗里，把 `shell` 从「自动」改成一个具体值（例如 `/bin/sh`），点「保存 shell」。

- ✅ **通过**：按钮短暂变成「已保存」；**关掉弹窗再打开**，下拉框仍是刚选的值。
- ❌ **不通过**：显示保存失败；或重开后变回原值。
- 📝 **记录**：截图 + `docker compose logs backend --tail 50`。
- ⚠️ **注意**：这一项**会真的改**你的 `~/.config/opencode/opencode.jsonc` 里的 `shell` 字段（只改这一个）。
  不想留痕就改回「自动」再保存一次。

### 1.11 终端（PTY）

界面上打开内置终端（如果当前页面有终端入口）。

- ✅ **通过**：终端能敲命令、有回显（例如敲 `ls` 能看到文件列表）。
- ❌ **不通过**：黑屏、无回显、一直「连接中」。
- 📝 **记录**：截图 + Network 面板里 `connect-token` / `pty` 相关请求的状态码。

## 2. WSL 形态（Windows + WSL）

> 只在 Windows 上做。前置：WSL 里已装好 **v2** 的 opencode。

### 2.1 先确认 WSL 里的 opencode

在 **Windows 终端**里执行：

```bash
wsl -d <你的发行版名> -- sh -lc '$HOME/.opencode/bin/opencode --version'
```

- ✅ **通过**：输出 `opencode v2.x.y`。
- ❌ **不通过**：
  - 提示找不到文件 → 在 WSL 里跑 `curl -fsSL https://opencode.ai/v2/install | bash`。
  - ⚠️ **注意路径**：本 UI **只认 `$HOME/.opencode/bin/opencode`** 这一个位置
    （与官方桌面版一致）。如果你是用 npm/bun 全局装的（在 `/usr/local/bin` 等），
    请**另装一份**到上面那个路径。
- 📝 **记录**：上面命令的**完整输出**（含报错）。

### 2.2 在 UI 里添加 WSL 服务器

设置 → 服务器 → 添加 → 选 WSL → 选发行版。

- ✅ **通过**：发行版列表能刷出来；选中后显示「就绪」；能点「添加」。
- ❌ **不通过**：
  - 列表空 → WSL 探测失败。
  - 显示「未安装 opencode」但你明明装了 → 见 2.1 的⚠️（路径不对）。
  - 显示「需要更新」→ 按提示点更新。
- 📝 **记录**：截图（含状态文字）+ WSL 里 `ls -l $HOME/.opencode/bin/opencode` 的输出。

### 2.3 启动 + 健康检查

添加后，在该服务器上发一条消息。

- ✅ **通过**：服务器状态变成「运行中」；消息能发出并收到流式回复。
- ❌ **不通过**：状态变「失败」。
- 📝 **记录**：失败时界面上显示的**错误文字原文**（它包含 WSL 里最近的 12 行输出，信息量最大）。

### 2.4 安装按钮（如果前面显示未安装）

点「安装 opencode」。

- ✅ **通过**：等待一段时间后状态变「就绪」；版本是 `v2.x`。
- ❌ **不通过**：报网络错误 → 检查 WSL 里能否访问 `registry.npmjs.org`
  （v2 安装脚本从 npm 取包，国内网络可能较慢）。
- 📝 **记录**：错误原文 + WSL 里 `curl -I https://registry.npmjs.org` 的结果。

## 3. Tauri 桌面形态

> 🔴 这一节里有**两条至今没在真机上验证过**的项目（本清单的重点）。

### 3.1 基本启动

打开桌面应用。

- ✅ **通过**：窗口出现；能自动发现并启动本地 opencode；能发消息收到流式回复。
- ❌ **不通过**：窗口空白；或提示找不到 opencode。
- 📝 **记录**：截图 + 应用日志（设置里若有「查看日志」）。

### 3.2 🔴 未实测项 A：终端「先取 ticket 再连」

打开内置终端，敲一条命令（例如 `pwd`、`ls`）。

**背景**（为什么单列）：V2 的终端连接协议改了 —— 必须**先向服务端要一张一次性票据（ticket）**，
再用它去连 WebSocket。浏览器形态已验证通过，但**桌面形态（走 Tauri 的 HTTP 通道）从未在真机跑过**。

- ✅ **通过**：终端能正常输入输出，命令结果正确显示。
- ❌ **不通过**：终端空白 / 一直显示连接中 / 立即断开。
- 📝 **记录（关键）**：
  1. 截图；
  2. 应用日志里 `pty` / `ticket` / `connect-token` / `websocket` 附近的**原文**；
  3. 若能看到网络请求，记下取票据请求的状态码（200 / 401 / 403 / 404）。

### 3.3 🔴 未实测项 B：SSE 流式在桌面 HTTP 通道下的表现

发一条会**长回复**的消息（例如「用 300 字介绍你自己」）。

**背景**：桌面形态下，网络请求由 Tauri 的 `plugin-http` 代发（为了绕过浏览器的跨域限制）。
流式响应（SSE）能不能**边收边显示**，在这种通道下**从未验证过**。

- ✅ **通过**：回复**逐字/逐段**出现（像打字机），不是「等很久然后整段蹦出来」。
- 🟡 **可接受但要记录**：回复是整段出现但内容正确 —— 说明流式退化成了一次性返回（体验差，但不算坏）。
- ❌ **不通过**：永远收不到回复；或回复到一半卡死。
- 📝 **记录（关键）**：
  1. 是「逐字出现」还是「整段出现」（很重要，请明确写）；
  2. 从回车到第一次出现文字的**大概秒数**；
  3. 应用日志里 `SSE` / `subscribe` / `stream` 附近的原文。

## 4. 多服务器形态

### 4.1 切换

添加两个服务器（例如一个本地、一个 WSL/远程），在两者之间来回切换。

- ✅ **通过**：切换后**会话列表跟着换**（不会把 A 的会话显示在 B 里）；消息历史正确。
- ❌ **不通过**：切了之后列表不变；或显示的是**另一个服务器**的会话。
- 📝 **记录**：两个服务器的地址 + 截图（能同时看到服务器名和会话列表）。

### 4.2 并发

在服务器 A 上发一条**长回复**的消息（不要等它结束），立刻切到服务器 B 并发一条。

- ✅ **通过**：两边的回复**各自独立**地正常流式输出，互不串台；A 的回复不会跑到 B 里。
- ❌ **不通过**：B 里出现 A 的回复；或 A 的回复中断；或切换后界面卡死。
- 📝 **记录**：截图 + Console/日志报错。

### 4.3 断线重连

把某个服务器停掉（或拔网线），等几秒再恢复。

- ✅ **通过**：界面提示断开 → 恢复后**自动重连**并能继续收消息。
- ❌ **不通过**：一直显示断开、不自动恢复（需要手动刷新页面）。
- 📝 **记录**：等待了多久 + 是否手动刷新才好。

## 6. 怎么反馈

不通过时，请把下面这几样一起给我（缺一不可，否则很难定位）：

1. **哪一步**（例如「§1.6 中断」）；
2. **点哪里 → 期望看到什么 → 实际看到什么**；
3. **截图**（含地址栏/界面状态）；
4. **报错原文**（Console 红字 / 日志，**请复制文字而不是只截图**）；
5. **版本信息**：`opencode --version`、本 UI 版本（设置里能看）、
   Docker 的话再加 `docker compose images`。
